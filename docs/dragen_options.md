# seqeralabs/nf-dragen: DRAGEN options

This page checks every DRAGEN option the pipeline passes against the Illumina DRAGEN **v4.4** product guide (checked 2026-11-20). The `help.connected.illumina.com` links redirect to `help.bioinsight.illumina.com`.

Verdicts:

- **ok**: matches the docs.
- **wrong**: the docs show a different value or flag. These are fixed. None was found; one missing flag is fixed (see `--sv-exome`).
- **missing**: the docs recommend it and the pipeline does not pass it. These are not added when they need a new input or param.
- **ignored**: DRAGEN accepts the flag, but it does nothing here or repeats the default.

## Questions

**Does exome SV calling need an exome-specific flag?** Yes. `--sv-exome true` must be passed: the [SV page][SV] says "If not directly set, exome mode defaults to false", and `--sv-call-regions-bed` does not turn it on. Exome mode disables the high-depth filters. The [somatic WES recipe][SWES] passes both. Fixed for somatic exome runs.

**Is `--sv-call-regions-bed` right for exome?** Yes, it is the option the v4.4 [WES recipes][SWES] use. The v4.4 [SV page][SV] documents the same behaviour under the name `--sv-target-bed` (SVs with both breakends in the regions are called) and offers `--sv-locus-node-target-file` for calls with at least one breakend in the regions. The pipeline keeps the recipe's name. Check in the first real Platform run that DRAGEN accepts `--sv-call-regions-bed` without a deprecation warning.

**What are the tumour/normal output names?** Compared with the tumour/normal outputs of `modules/local/dragen/main.nf`:

| Output                       | Pipeline expects                                             | Docs                                                                                            | Verdict                                                            |
| ---------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Hard-filtered small variants | `<prefix>.hard-filtered.vcf.gz`                              | [SOM]: "`<output-file-prefix>.hard-filtered.vcf.gz`"                                            | ok                                                                 |
| Unfiltered small variants    | `<prefix>.vcf.gz`                                            | not named                                                                                       | check in the first real Platform run                               |
| SV                           | `<prefix>.sv.vcf.gz`                                         | [SV]: "`<output-file-prefix>.sv.vcf.gz`", same name for germline, tumour/normal and tumour-only | ok                                                                 |
| CNV (WGS)                    | `<prefix>.cnv.vcf.gz`                                        | not named in the pages read                                                                     | check in the first real Platform run                               |
| Tumour and normal BAMs       | `<prefix>*.bam` (stub: `<prefix>_tumor.bam`, `<prefix>.bam`) | not named                                                                                       | check in the first real Platform run; the glob accepts either name |
| Metrics                      | `<prefix>.*metrics.csv`                                      | [SOM] names `*.allele-transition-noise-metrics.csv`; others not listed                          | check in the first real Platform run                               |

No output name was changed: the docs name nothing that differs from the module.
